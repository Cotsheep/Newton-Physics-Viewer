# 摔落量化观察：首次 GPU 验证

准备日期：2026-09-27。本文是待执行的验证计划，不是服务器通过记录。测量定义见[结果观察数据约定](../docs/结果观察数据约定.md)，最终验收见[物理方案 F01–F08](../docs/Newton–MuJoCo%203D%20资产物理合理性仿真检查方案.md)。

## 本次范围

复用已经入库并完成过录像的 Artiverse 剪刀派生功能测试版本，仅运行一次中档 GPU 摔落录像，核对新增测量与页面链路。资产 identity、完整版本及实际配置取自被忽略的本地进展记录，不重新上传、转换或入库。该资产仅验证代码功能，不证明原始物理参数准确。

保持已有单 trial、单 GPU、无重试、1 秒物理过程、0.001 秒步长、1000 步及外层 8 分钟限时。录像保持 0.5 秒初始展示与 1 秒运动，共 75 帧。使用原只读图形库挂载及每次任务的节点驱动检查，不新增探针、安装依赖或放宽设备匹配。正式 profile 仍为 `reserved_not_runnable`。

## 按步骤部署

以下步骤由操作者逐步执行，每步收到证据后再给下一条实际命令，不一次粘贴整套流程。

1. 本地确认提交范围，经用户明确授权后提交并通过 Git 推送。私人配置、资产、日志和预览不进入提交。
2. 用户在服务器个人代码目录检查当前 HEAD 和工作树，再 fast-forward 更新到准确新提交；出现本地改动或分叉则停止，不重置或覆盖。
3. 从干净服务器 checkout 用 `experiment_runner.release` 生成全新源码导出，核对完整提交及来源清单。保留旧导出，不从本地脏工作树制作部署包。
4. 从原成功配置另存新文件，仅修改任务名称和准确新提交。保留资产版本、解释器、挂载、驱动核验、资源和限时。新提交未知前不制作带虚构 commit 的可执行配置。
5. 用户创建 paused experiment，核对平台接受的版本、入口和资源后再激活。每次仅创建一个，不自动重试；失败保留原始产物。
6. 根据新 run ID 校验本次产物、读取下表字段，再按已有结果服务及回环 SSH 隧道查看录像和新页面。不假定旧服务与隧道还在运行。

## 本次需要的证据

既有 GPU、录像和文件一致性要求沿用[GPU 录像说明](GPU_VIDEO_SMOKE.md)，新增检查如下：

| 检查项 | 本次预期 | 未达到时如何解释 |
| --- | --- | --- |
| 版本绑定 | manifest 的源码提交为本次新提交，资产版本为原功能样本确定版本；保留 `authoritative=false` | 旧版本结果不能验收新实现 |
| GPU 物理与渲染 | 实际 `cuda:0`、无 CPU fallback、1000 步、有限状态；NVIDIA EGL 与已分配 CUDA 设备匹配 | 整次运行不能作为成功验证 |
| 测量来源 | `drop_measurement` 记录编译碰撞几何、已完成步的 Newton 位姿、地面及资产形状 ID；诊断计算标明 CPU 只读 | CPU 几何统计不等于 CPU 物理解算；不得隐藏或改写该来源 |
| 采样完整性 | 三项观察定义为 `whole-asset-plane-clearance-first-flight-v1`；间隔 0.001 s，数量 1001（含初始），时窗 0–1 s | 缺样、非有限值、协议不一致不能按完整测量展示 |
| 初始净空 | 有限且大于 0.00001 m；页面分别显示配置与实测净空，比例使用实测初始值 | 不要求与旧取景边界得到的配置高度完全相等 |
| 首次回弹 | 若完整观察到触地、整体离地、再次落地，显示高度、比例与峰值时刻；否则显示相应未观察到/未完成状态 | 1 秒不足以完整观察时是有效边界状态，不补零、不自动延长工况 |
| 最大穿透 | 完整采样时显示非负有限深度，单位米；正值带采样时刻，零不展示虚假的发生时刻 | 不能从录像、取景边界或旧结果重建 |
| 索引与页面 | 三项观测和实际采样时窗与 case 一致；微小穿透不舍入成零；旧记录仍为未测量 | 页面正常不等于物理有效性通过 |
| 参数快照 | 新 manifest 保存该版本 USD 输入快照，缺失/未知来源如实显示 | 包内标注不等于求解器最终接触参数；F05 尚未完成 |
| 耗时 | 保存 `setup_wall_seconds`、`sampling_wall_seconds` 和本次 `wall_elapsed_seconds` | 这是含同步/回传的诊断耗时，不能与跨节点历史总时长相减来估计净增开销 |
| 人工观看 | 模型、运动、参考面与画面尺度正常；明显离地与测量状态无矛盾 | 录像每 20 步取帧，不可用于确认每步微小穿透或精确峰值 |

本次无需为了得到某个回弹数值而调参数。`unsupported`、`invalid` 或完整采样缺失意味着测量接入尚待处理；`not_observed`、`no_liftoff` 或首次飞行未结束可以是窗口内的有效观察状态，但不构成完整回弹数值验证。

## 通过后的边界

本次最多确认指定样本、指定节点上的新测量接入、基本一致性和实际诊断耗时。单次运行没有同条件关闭测量的基线，不能证明净性能开销可忽略；固定步长采样也不能证明连续运动极值准确。步长敏感性、覆盖首次完整回弹的受控参考案例、完整接触参数来源，以及多高度/坡度与比较功能仍需后续验证，F06 和最终验收不能据此直接关闭。

2026-09-24 已完成的 70 项 Python 与 7 项前端检查属于历史本地证据；本准备步骤不重跑它们。新服务器结果应按实际执行日期写入本地进展记录，环境笔记只保存配置和问题处理。
