# Newton-Test 后续验收与协作提示词

更新日期：2026-09-21。本文是公共的操作约定，不包含实际服务器地址或运行编号。新对话的具体接手入口由本机 Git 忽略目录 `deployment/local/` 中的交接文件提供。

## 先理解当前进度

先读 [当前状态与下一步](CURRENT_STATUS.md)、[部署说明](README.md)、[GPU 录像说明](GPU_VIDEO_SMOKE.md)，再按任务需要读 README、CONTEXT、ADR 和实现。历史验收报告反映各自日期，不覆盖后续真实 trial 证据。

测试小方块的共享存储、预制 Python 环境、单 GPU 物理解算、NVIDIA EGL 渲染、视频文件校验及手动 SSH 浏览已验证。下一步是接入一个真实资产，源目录和格式仍待用户提供。不要从首次部署或首次 GPU 冒烟重新开始。

正式多高度、多坡度和批次能力仍未开放。正式 profile 必须保持 `reserved_not_runnable`、`runnable=false`，不能把一次冒烟当作正式物理结论。服务器使用 GPU 仿真和 GPU 渲染，CPU 软件绘图不作为回退；FFmpeg/libx264 的 CPU 编码是另一件事。

## 工作方式

1. 用中文沟通。本地可做的检查自行完成；服务器由用户执行，每次仅给一个小步骤，说明执行位置、目的和需返回的输出，收到结果后继续。不自动 SSH、连接真实 Master、创建或激活任务。
2. 保留已验证事实；仅在代码、依赖、环境变化或新失败出现时补做相关检查，不无理由重跑完整测试或探针。
3. 实际参数来自已确认配置，不猜路径、资源池、节点或资产。带占位符的内容只能作为模板，不能直接让用户粘贴执行。
4. 原资产、环境、源码导出和下载包均保留；不删除或直接移动原件，不使用带删除选项的同步。`accept-asset` 会移动 inbox 暂存副本，必须先复制源包，并明确说明这一入库动作。
5. 真实路径、地址和配置放在被 `.gitignore` 覆盖的 `deployment/local/` 或服务器私人配置中。该目录不加密，不保存密码、令牌或私钥。不索取完整环境或含 registry 凭据的未脱敏 experiment config。
6. 代码通过 Git 更新个人目录，不采用离线 bundle。修改和本地检查在授权范围内推进；提交、推送另需用户明确授权。本次文档整理不包含 Git 提交授权，不还原用户改动。
7. 不使用 sudo、Docker socket、其他人的 HOME 映射；不修改宿主机驱动或全局配置，不伪造 `DET_*`、GPU UUID 或来源清单。既有可变镜像标签是用户接受的选择，不为 digest 再索取权限。

## 真实资产的下一步

先取得一个真实资产的服务器源目录和格式，逐步只读核对路径、权限、完整包结构及复制所需空间。选择一个小样本复制到独立 inbox，校验内容后才验收入库。以组合入口 `newton-mujoco.usda` 和包内依赖为准，不把 Viewer 的其他格式支持当作试验支持。

入库和 readiness 报告需如实显示缺失项；不能为了运行而猜补质量、惯性或接触参数。若资产不满足要求，停在对应问题上修正，保留原包，不继续提交 GPU。

随后复用已验证的环境、源码导出和图形库配置，填入真实资产的确定 identity/version，运行一次有界单 GPU 摔落录像。先小样本验证，再讨论全量迁移或正式多工况开发。

## 来源、配置与提交

本地先检查分支、HEAD 和工作树；未 fetch 时远端关系只代表缓存。源码变化后运行相关测试，取得干净确定 commit，再通过既有 release 工具生成新导出。不修改旧导出或伪造 `.newton-source.json`；同一版本仅改变任务配置时可复用导出。

Python 3.12 和锁定运行依赖在 GPU 分配前准备。共享环境同时包含基础 Python 和 venv，以相同绝对路径只读挂载；项目从上传源码加载。项目入口不做依赖解析、下载或安装。平台自身启动时的 pip 行为与项目 venv 分开判断。

录像配置保留：单 trial、单 GPU、明确资源池、无重试、临时目录 checkpoint、外层 8 分钟及 30 秒终止宽限、固定 1000 步、无 CPU fallback。图形用户态库单独只读挂载，启动 Python 前核对实际节点驱动，再设置库搜索路径和 EGL vendor 文件。通用模板不自动包含这份集群适配。

由用户创建 paused experiment；核对平台解析后的挂载、解释器、资产、commit、入口及资源配置，再由用户激活该 ID。不要自动重试或重复建任务；编辑服务器 YAML 不会改变已经创建的 experiment。命令语法不确定时先检查已有 help 或官方文档，不凭记忆猜参数。

## 验收证据

成功需要调度状态、程序状态、设备证据和文件内容相互一致：

- trial 结束、退出 0、资源释放；manifest/status/case 成功且 `authoritative=false`。
- 资产版本、源码 commit/指纹及锁定依赖与配置一致。
- 唯一分配的 GPU、逻辑 `cuda:0`、runtime UUID 与 allocation 身份核验匹配，实际物理解算无 CPU fallback，1000 步完成且数值有限。
- 带录像时 `recording.status=succeeded`，NVIDIA vendor、EGL/CUDA 设备匹配及实际取帧成功；无录像入口应为 `not_attempted`，不能要求它生成视频。
- 校验清单路径先限定在选定 run 目录，再核对全部文件哈希。录像还要用 ffprobe 检查实际编码、尺寸、帧数和时长，并人工观看画面。

mock、文件存在、进程退出 0 或 `allocation stopped early` 某个短语均不能单独决定业务验收。失败保留 case 中的阶段和 `recording.diagnostics`，按证据修正受影响部分；不降低设备匹配规则，也不补写成功状态。

结果查看继续使用两端 `127.0.0.1` 的手动 SSH 隧道和远端 `serve-results`。HTTP 接口只读，启动服务会准备页面和索引；不申请 GPU，不提供 Web 提交/删除。手动通道通过不意味着自动菜单或常驻服务已经验收。
