# 外部只读 USD 资产

2026-10-04：本地实现；尚未部署或使用学长的公共资产进行服务器验收。现有 GPU 调度门、录像要求和未开放正式 profile 保持不变。

## 两种接入方式

| 项目 | 版本入库 `accept-asset` | 外部只读 `register-external-asset` |
| --- | --- | --- |
| 输入位置 | 先复制完整包到自己的 inbox | 指定公共资产的源目录和 USD 入口，原位读取 |
| 写入行为 | 将 inbox 副本原子移到 assets，设为只读 | 只在自己的数据目录写登记信息与报告，不复制、移动、链接或 chmod 源文件 |
| 额外资产空间 | 保留一份自己的完整依赖包 | 无额外资产副本；仍需登记、报告、结果、视频和运行缓存空间 |
| 输入版本 | 自己保存的不可变内容版本 | 入口和完整依赖的内容指纹，运行前后复核；外部存储本身不受本程序控制 |
| 源文件变化 | 已入库副本不受影响 | 旧版本不可运行，需明确重新登记新版本 |
| 历史复现 | 已保存内容可重用 | 依赖所有者继续保留相同内容；登记信息不能恢复被覆盖或删除的文件 |

两种方式共享 USD 依赖解析、必需物理参数检查、逐模板 readiness 和运行入口。读取方式不会证明资产的物理合理性，也不会放宽缺失质量、惯性或接触参数时的阻断。

入口根层还必须明确声明米制 `metersPerUnit=1` 和合法的 `upAxis`（Y/Z）；不能把下层资产的声明当成入口声明。当前 Newton 导入器不转换非米制或非千克单位，预检会阻断这些入口。质量单位允许 USD 标准千克默认值，也可明确声明 `kilogramsPerUnit=1`，不会写回任何默认值。`asset-readiness-v3` 新增该检查，旧登记记录在选版本时重新预检；缺失时需要来源方提供明确入口，本程序不代改公共 USD。

## 登记与选择

在能读取完整源目录的机器上，用本项目的 Python 执行以下命令。路径是占位示例，部署时使用自己的数据根目录和已获准读取的公共资产路径：

```bash
python -m experiment_runner.cli register-external-asset Shared/props/box \
  --source-root /path/to/shared/package \
  --entrypoint models/box.usda \
  --source-name Shared \
  --data-root /path/to/project/data
```

`--source-root` 必须是绝对、真实目录，包含入口及全部依赖；尽量选择包含依赖的最小公共目录。`--entrypoint` 是其下的相对 `.usd`、`.usda` 或 `.usdc` 文件，不要求改名为 `newton-mujoco.usda`。入口可引用同一源根内的兄弟目录；缺失依赖、越界依赖、符号链接及 Windows junction 均拒绝。源目录与数据目录不能相同、互相包含。不同读取方式不能共用一个资产身份；一个外部身份不能被悄悄改绑到另一来源路径或入口。

命令返回 `registered` 或 `duplicate` 时表示登记完成。物理字段缺失或无效仍可登记以查看预检结果，但相应模板为 `not_ready`，不得运行。关注 `template_readiness`、`ready_templates` 和错误原因，不能把登记完成当成试验通过。

```bash
python -m experiment_runner.cli list-assets --data-root /path/to/project/data
```

列表中的 `storage_mode=external_readonly` 表示原位读取。菜单会复核外部版本，再展示当前就绪状态；不可访问或内容变化的版本不进入可运行选项。运行沿用现有命令的 `identity version` 参数，例如 `smoke-drop-gpu` 或 `validate-drop-gpu --height low`；其调度、设备和源码限制仍全部适用，登记命令不会提交或启动实验。

数据根目录布局：

```text
asset-references/<identity>/<version>/registration.json  # 来源路径、入口、依赖、预检
import-reports/import-*/report.json                     # 每次登记尝试的报告
runtime/runs/<run-id>/                                  # 参数快照、输入复核、录像和结果
assets/<identity>/<version>/                           # 仅属于现有版本入库模式
```

旧数据目录无需重新初始化：首次登记按需创建 `asset-references`。不会向公共资产目录写报告、临时文件、视频、缓存、锁或索引。登记记录及原始运行 manifest 含源绝对路径，用于个人追溯；浏览器摘要只展示来源名称、读取方式和复核结果，不添加公共目录浏览或下载接口。

## 内容变化与版本约定

外部版本为 SHA-256，绑定 `external-readonly-v1` 域、入口相对路径以及按文件相对路径、字节数、SHA-256 排序生成的完整依赖指纹。同一依赖集合的不同 USD 入口也得到不同版本。它与现有入库版本算法分开，已有资产哈希不变。

运行准备时重新解析依赖并计算指纹，重新读取当前物理参数。GPU 初始化前、场景加载后和运行结束时再次复核完整依赖的内容及文件状态；检查点间出现可检测的修改、替换、删除、越界或读取失败时，本次运行记为失败，保留原因和已有证据，不报成功。文件原字节被恢复但文件状态发生变化，也会拒绝该次运行。结束复核通过时，manifest 的 `asset_input_verification.stage` 为 `after_run`，浏览器详情显示各阶段与所选版本一致。

这不是冻结外部文件或锁住所有者。检查不能保证发现检查点之间发生又完全恢复、且文件状态也被恢复的瞬时修改；已验证的版本也可能在未来被删除。因此运行期间源包应保持稳定。需要长期复现保证时使用现有入库模式，或由资产所有者提供稳定、保留的版本目录。完整哈希检查有磁盘读取成本，但不占用另一份资产空间。

## 服务器接入与验收

在服务器上登记后，任务必须能访问登记记录中的**相同绝对源路径**。公共源目录应单独以 `read_only: true` 挂载；自己的数据根目录仍可写，Python 环境和图形库继续只读挂载。宿主机路径与容器路径的对应关系由服务器现状确定，不根据登录容器的路径猜测。不能只挂载 USD 文件却漏掉纹理、网格和子层。登记程序不会修改挂载配置或资产权限，也不把应用的只读访问宣称为宿主机文件系统的冻结。

实际验收应先选择一个小样本：确认入口、完整依赖和模板就绪，登记前后对比源文件内容及目录树；确认自己的 inbox/assets 没有新增资产副本，登记与报告只在个人数据根；再在操作者明确提交的有界 GPU trial 中确认场景、录像、版本和三阶段复核。更换源内容后旧版本必须被拒绝，且无 GPU 初始化。GPU 路径的本地 mock 测试只验证程序分支，不替代真实服务器运行证据。
